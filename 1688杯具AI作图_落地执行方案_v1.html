00. 已锁定的决策

事项结论
目标定位做成服务（对外部商家可用），先自己 6 个店用；一步到位按 SaaS 标准建，自测期也按对外标准
开发方式用户自己的 AI 系统开发（AI 写代码 + 人验收），不外包
CorelDRAW录音中的“CCD/CCDR”确认为 CorelDRAW（CDR），是美工现用工具；系统需与它衔接而不是绕开它
时间无硬性死线，越快越好
现行成本基准专职美工 1 名，月薪约 6,000–7,000 元（无按套计价）；ROI 对标此口径
原报告裁决架构与选型保留；本文补定位、门槛、合规、节奏、ROI 五件事

01. “SaaS 标准一步到位”的正确打开方式

一步到位 = 数据模型、合规钩子、账本、隔离第一天就按对外标准；功能按阶段上。避免两个极端：内部工具后期推倒重来，或一上来堆支付/客服拖死进度。

01.1 第一天就要按对外标准的（后补即返工）

项要求
多租户数据模型users / workspaces / memberships；所有业务表带 workspace_id，行级隔离。自己 6 个店 = 6 个工作区，以后商家各一个
鉴权手机号 + 微信登录（云服务现成能力）；角色 owner / admin / member
成本记账provider_costs 表按 workspace 记账，单套成本随时可查——这是以后定价的地基
审计与版本成品版本、商品资料版本、关键操作留痕
合规钩子导出前强制过“极限词 / AI 标识 / 图规 / 字体”四道校验位（§04）。可以做成配置开关，但代码位第一天就在
API-first所有能力走 API，网页只是第一个客户端；方便以后接商家工具、1688 服务市场
标识元数据导出文件写隐式标识（§04.2），从第一张成品图就带

01.2 可以后补的（不阻塞上线）

支付 / 套餐 / 发票（内测免费）· 工单客服系统 · 多语言 · LiteLLM 网关 / LangGraph · 桌面 PS 执行器 · PSD 导出 · 视频 / 3D / CAD · n8n / Dify 运营集成。

03.3 出口判定

  • 10 款中 ≥ 7 款达标（其中玻璃、反光款至少各 1 款达标）→ 进入 Stage B 全量开发
  • 达标 4–6 款 → 走“保守路线”（保留商品主体 + 场景合成为主，接受部分人工），先服务自己 6 个店
  • ≤ 3 款达标 → 暂停建站，先解决素材/抠图/模型选型；损失控制在 50 元 + 1–2 天

04. 合规补丁（四件套，全部是导出前强制校验位）

04.1 广告法极限词表

  • 规则表 forbidden_words（“最”“第一”“极致”“国家级”“顶级”等绝对化用语，可维护），文案生成后、导出前逐条匹配
  • 命中 → 阻断导出并给出高亮改写建议；词表维护入口放管理端
  • 依据：广告法禁绝对化用语；1688 是职业打假高发区，此项成本极低、必须有

04.2 AI 生成内容标识（《人工智能生成合成内容标识办法》，2025-09-01 施行）

  • 显式标识：成品图默认带用户可感知标识（角标/水印，样式可配）；提供下载、导出功能时，文件中必须含满足要求的显式标识
  • 隐式标识：文件元数据写入生成合成属性信息、服务提供者名称/编码、内容编号等要素（对齐配套强制性国标《网络安全技术 人工智能生成合成内容标识方法》）
  • 若用户申请无显式标识版本：用户协议中明确其标识义务与责任，并将相关日志留存不少于 6 个月（监管提示口径）
  • 定性要求：商品宣传图必须图实一致，AI 只做场景与氛围渲染、不改动产品本身——与报告“保留商品主体合成”路线一致
  • 存证：底图原图 + 生成记录 + 成品按款归档（对抗盗图与纠纷举证，也符合 1688 原创保护实践）

04.3 1688 类目图规校验（做成可配置规则）

  • 程序校验：主图最小 800×800、尺寸/格式、类目要求时的白底占比、文字区域占比、禁元素清单（虚构模特、误导文字等）
  • 不达标 → 导出前拦截；规则放配置表，按类目扩展
  • 具体条款以商家后台现行规则为准，M4 内测前逐类目核对一遍

04.4 字体白名单

  • 仅允许白名单字体：思源黑体/思源宋体（SIL OFL）、阿里巴巴普惠体、HarmonyOS Sans 等可商用字体
  • 模板只能引用白名单字体；字体文件与 LICENSE 一并入库；服务器字体与前端字体度量对齐（报告已列要求）

05. CorelDRAW（CDR）衔接与导出包

美工现用 CDR 做图。系统不是换掉他，而是把“从零做图”变成“出稿 + 精修”，人转为终审、精修、模板沉淀。

导出包结构：

final/       1688 直接用：主图 800×800 JPG、详情段 750 宽 PNG（含显式标识）
editable/    可编辑 PDF 或 SVG（文字不转曲），CorelDRAW 直接打开继续改
design.json  设计数据（版本化，回炉改字/换图不必重做）
report.md    本套校验结果、模型版本、成本明细、AI 标识与存证记录
  • 交付语义三态：READY（7 张全可用）/ READY_PARTIAL（标注哪几张可直接用）/ NEEDS_REVIEW
  • 隐式标识写入 final/ 与 editable/ 两类文件的元数据

06. 开发路线（AI 系统开发 + 人验收）

06.1 协作原则

  1. 规范先行：每个模块先落“验收标准 + 接口定义”（本文档就是第一份），再让 AI 实现；改需求先改文档再改代码
  2. 里程碑按可运行物验收：不看代码量，看能不能跑通真实素材
  3. 人工把三关：需求验收；关键路径 code review（预算、幂等、标识写入、租户隔离四处）；真实打样回归
  4. 每个里程碑都用真实杯具素材跑：固定 3 个样杯做回归集，防止“演示能跑、上真图翻车”

06.2 里程碑（按周节奏，AI 开发下可压缩）

里程碑可运行物出口条件
M0 打样独立脚本：输入实拍图 → 出 7 张样图§03 硬门槛判定完成，做出进退决策
M1 管线CLI 全流程：上传→理解→策划→生成→合成→导出（含四道校验）3 个样杯各出 1 套，成本/日志落库
M3 SaaS 底座多租户、鉴权、账本、审计、管理端（词表/规则/字体）新建 workspace 全流程跑通，成本报表可看
M2 Web上传、任务进度、改字选稿、导出（React + Konva）你自己不用命令行能出一套图
M4 内测6 个店真实上新使用 + 2–3 位外部商家每套终审 ≤ 15 分钟；连跑 2 周收数据

建议顺序：M0 → M1 → M3 → M2 → M4。底座趁表少早建（一步到位的关键），Web 可以晚于底座，但不能晚于内测。

07. 成本与 ROI（对标美工 6–7k/月）

07.1 现行基准

美工月薪 6,000–7,000 元。月产 N 套 → 人工成本 = 6,500 ÷ N 元/套：

月产套数50 套100 套200 套
人工成本/套约 130 元约 65 元约 32.5 元

07.2 AI 路线现金成本（报告算例口径，待实测）

  • 模型调用约 4–8 元/套（16 张候选素材口径 4.17 元）；云资源 150–350 元/月（内测期 150 元档起步）
  • 终审若由运营/你兼做（10–15 分钟/套），边际现金成本极低
  • 开发人工 = 你自己的时间 + AI 系统，无外包支出；300 元验证预算不变

07.3 判断

  • 给自己 6 个店用：省的不是美工工资，是上新速度与产能上限；美工从“全手做”转“终审+精修+模板”，人效放大
  • 做成服务：单套现金成本 4–8 元，对比市面按张/订阅工具（鲁班设计、稿定 AI 等）有明确定价空间；具体定价待 M4 内测数据 + 竞品调研后定
  • 止损线：Stage A 不过线，50 元 + 1–2 天结束，不进大开发

10. 部署与技术栈直答（云 vs 内网穿透、Electron vs Python）

10.1 一句话结论

  • 部署用云服务器，不用内网穿透：国内云主机（2 核 4 GB 起步）+ Docker Compose，程序 7×24 常驻。
  • 形态是网站，不是桌面软件：既不用 Electron，也不是“用 Python 写个客户端”；商家和你都用浏览器打开网址。主力后端 Node.js/TypeScript + 专职 Python 抠图小进程（报告口径）；若你的 AI 开发系统输出 Python 更顺手，可整体换 FastAPI，架构不变。

10.2 云服务器 vs 内网穿透

维度国内云服务器（推荐，正式必选）内网穿透（frp / Cloudflare Tunnel / 花生壳）
稳定性常驻运行，商家随时访问依赖你那台电脑开机、不睡眠、网络不断、桌面会话正常
适用场景对外服务的标准做法临时演示、自己一个人用
多商家并发天然支持你电脑就是瓶颈
域名与备案国内域名需 ICP 备案（约 1–3 周，买服务器时同步办，与开发并行）不能替代合规入口
结论M4 内测前必须就位只可当备案期间的临时试用通道

Cloudflare Tunnel 的本质是“把内网机器暴露到公网”，程序仍跑在那台机器上；它的中国大陆网络是单独的企业服务，不适用本项目。

10.3 Electron：不用

Electron 是把网页打包成桌面软件（类似飞书桌面版）。做成服务给商家用，要求“发个网址就能用”，商家零安装；桌面安装包还会带来升级、杀毒误报、多版本分发的麻烦。首版形态 = React 网页（改稿编辑器 React-Konva 也在浏览器里跑）。

例外：以后若有商家坚持要桌面壳，可以用 Electron 套同一个网页——那只是壳，服务端仍在云上，架构不用改。

10.4 Python 的位置（“Electron 还是 Py”的正确拆法）

报告口径：Node.js 主力 + Python 专职抠图。如果你的 AI 开发系统输出 Python 更顺手，可按下表等价替换，架构图不变：

位置报告默认（推荐）等价替换（更熟 Python 时）
网页前端React + TypeScript + Konva不变（浏览器端只能是 JS）
后端 APINode.js 24 + FastifyPython FastAPI
任务队列PostgreSQL + pg-bossCelery / arq，或继续用 PG 队列
图像排版合成Sharp + SVGPillow + CairoSVG（文字排版需多测字体度量）
抠图独立 Python 进程（rembg u2netp）直接内嵌 rembg
部署Docker Compose不变

说明：选 Node 主力的原因是 Sharp + SVG 的文字排版和字体度量最省事，Konva 编辑器本来就是 JS。两套都能跑通，选定后不要中途换语言。本文的门槛、合规、里程碑对两套完全适用。

10.5 什么东西跑在哪

位置跑什么
你 / 商家 / 美工的电脑只用浏览器打开网址；美工另用 CorelDRAW 打开 editable/ 精修。不装任何服务端
国内云服务器（2C4G 起步，邀请试用可按 4C8G 规划）Caddy（HTTPS + 静态网页）、API（账号/任务/额度）、Worker（调模型/抠图/合成导出，内含 Python 抠图进程）、PostgreSQL（数据 + 队列）
阿里云百炼qwen3-vl-plus（看图/审核）、qwen-plus（文案/策划），正式 API 出站调用

关键点：模型调用全是出站请求（云服务器主动连百炼/方舟），没有任何东西需要“从外面连进你电脑”——这正是不需要内网穿透的原因。

10.6 开发期省钱做法

M0–M3 在你自己电脑上跑同一套 Docker Compose；云服务器在 M4 内测前买好即可，备案提早同步办（不影响开发）。模型 API 按量付费，与程序跑在哪无关。云资源预算维持报告的 150–350 元/月规划额度，内测期取低档。

10.7 现有 2C4G / 60G 服务器评估

结论：够用，正好是本方案的起步档；60G 盘很宽裕。可撑完 M0–M3 开发和自己 6 个店的低量使用；M4 多商家内测时先到瓶颈的是内存，届时在线升配 4C8G 即可，架构与代码不用动。

内存预算（4GB，单任务并发口径）：

系统 + Docker 守护400–600 MB

Worker（Sharp 处理峰值）300–800 MB

原图/成品/导出包走 OSS，不占本机盘
余量约 25–30 GB

CPU（2 核）：模型推理在百炼/方舟云端，不吃本机 CPU；本机只做 Sharp 合成（快）和 rembg 抠图（每张几秒，先限 ~1024px 再抠）。单套 7 张可控在 10–15 分钟，10 SKU 打样一晚上跑完。

带宽（比磁盘更关键）：若是轻量服务器/低带宽规格（3–5Mbps 的“小水管”），前提是图片按架构直传 OSS（浏览器→OSS），不让大图走服务器中转；服务器只传 API 数据和网页，小水管完全够。若把上传也走服务器，带宽立刻成为瓶颈。

上云前核实两件事：

  1. 是否“突发性能实例”（t5/t6/t7 积分型）：云控制台看实例规格。突发型便宜，但连续图像处理会耗尽 CPU 积分被限速到很低性能，批量打样会非常慢。打样期能忍；M1 之后建议独享 CPU 的通用型/计算型（g/c 系列）。
  2. 是否国内节点：面向国内 1688 商家必须国内节点 + ICP 备案；香港/海外节点访问慢且无法备案，需要换。

升级路径（不够时的信号：多商家并发 OOM 或任务排队过长）：a) 云商在线升配 2C4G→4C8G，Docker Compose 原样迁移；b) 保持 2C4G 跑 API+DB，Worker 拆到第二台；c) 继续限并发换时间。
