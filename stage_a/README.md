## 三步

```bash
# 1. 生成模板（只写文件，不花钱）
python stage_a/run_stage_a.py --init

# 2. 把 10 张商品定稿图放进 stage_a/inputs/，填同名 .json 的商品事实
#    （文件名见 stage_a/inputs/放图说明.txt；参数见 事实核对表.csv）

# 3. 先零成本自检，再真跑
python stage_a/run_stage_a.py --check
python stage_a/run_stage_a.py --run
```

`--check` 不调用任何模型、不花一分钱，只检查图在不在、事实填没填、尺寸够不够。输入不齐时 `--run` 会直接拒绝执行。

其他用法：

| 命令 | 作用 |
| --- | --- |
| `--run --only cap_01` | 只跑一个 case 试水 |
| `--run --force` | 忽略已有结果重跑 |
| `--report` | 只重新汇总已有结果，不重跑 |

## 额度与成本策略

百炼 `qwen-image-3.0` 目前**只剩 5 张免费生图额度**，不够 10 个 SKU 各生成一张场景。
因此工具让 10 个 SKU **共用一张空场景**（`--scene-cache`，首次生成后落到 `stage_a/scene/neutral_scene.png`）：场景是无关变量，复用既省额度，也让「主体是否形变」的对比更干净。

看图与文案额度各剩 99 万+ Token，10 个 SKU 完全够。按线上实测单张约 0.005–0.006 元，10 张合计约 0.06 元，远低于 50 元预算；脚本仍会在累计超限时立即停止。

### 抠图模型（影响门禁公平性）

生产权重 `isnet-general-use.onnx`（Apache-2.0，171 MB，官方 MD5 `fc16ebd8b0c10d971d3513d564d01e29`）已从 GitHub 下载并校验通过。但**跨境回传只有约 16 KB/s**（171 MB 要数小时），所以权重保留在服务器 `/opt/cupimg/deploy/data/models/`，本机 `assets/models/` 里没有。

脚本逻辑：本地若有官方体积的 `isnet` 权重则优先用它；否则退回 `u2netp` 并在报告里标注。两者都不在时拒绝开跑，避免 rembg 静默联网下载卡死。

这一步很关键：轻量 `u2netp` 对金属高光、半透明盖件、细提环边缘抠得糙，拿它跑门禁可能把「抠图模型不行」误判成「整条 AI 路线不行」。因此若本地没有 isnet，**建议走服务器侧跑**：把 10 张定稿图传到首尔机，在容器内用 isnet 管线出图，只回传几 MB 产物，完全绕开 171 MB 回传。服务器侧权重已落盘、`rembg` 加载测试通过，容器内完整 live 实跑 `READY / 0.004 元 / 23.7s`。

## 产出与判定

| 文件 | 内容 |
| --- | --- |
| `out/scorecard.md` / `.json` | 自动项汇总表、成本、门禁状态 |
| `out/review_sheet.csv` | **人眼验收表**（用 WPS/Excel 填） |
| `out/compare/<case>.png` | 三栏对比：输入定稿图 / 成品主图 / 轮廓叠影 |
| `out/<case>/run.log` | 该 case 的完整 10 步流水线日志 |

轮廓叠影里**灰=重合、红=原图独有、青=成品独有**，两色分离即提示形变；IoU 仅供排序可疑样本，白色 Logo 与金属高光会造成噪声，不能当判据。

> **自动项通过 ≠ 过门禁。** `delivery=READY` 只代表程序硬校验通过。形变 / Logo 变字 / 提环与杯盖结构 / 反光结构 0 容忍，必须人眼逐张验收并填完 `review_sheet.csv`。工具在人工填完前一律报 `PENDING_HUMAN`，不会擅自宣布 PASS。

判定：人眼验收 10 张填完后，达标数 ≥7 **且形变不合格数 = 0** → 进开发；否则止损，不继续建站。
