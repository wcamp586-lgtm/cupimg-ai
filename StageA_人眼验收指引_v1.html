05 0 容忍清单

出现任一条，该 case 判 FAIL：

  • 杯身外轮廓变胖 / 变瘦 / 收腰位置移动 / 杯口杯底形状变化。
  • Logo 或印字变字、糊掉、缺笔、位置明显偏移、颜色被改。
  • 提环内孔被填实成实心、提环断裂、挂绳或背带整段消失。
  • 杯盖配件（视窗、饮口、球盖、卡扣）丢失、多出或变形。
  • 主体被裁切、被背景色啃掉一块、出现明显半透明残影。
  • 图上出现与定稿图不一致的新增图案、文字或道具。

06 哪些不算形变（别误判）

  • 白色 Logo / 印花 / 金属高光在轮廓比对里可能造成红 / 青噪点，属于算法对「非白像素」的判定噪声。
  • 透明底 PNG 渲染成灰底与白底成品之间的背景差异，不是主体变化。
  • 提环内孔、杯口内侧这类空腔区域的红 / 青块，要结合 1、2 栏肉眼确认：两边都空、形状一致，就不算形变。
  • 场景图、详情图里 AI 生成的背景 / 光影 / 排版本来就该变；0 容忍只针对商品主体。
  • IoU 低只是提示「值得多看一眼」，不能直接判 FAIL；IoU 高也不能直接判 PASS（小字变字不影响轮廓）。

07 怎么填 review_sheet.csv

每个 case 一行，按 review_sheet.csv 的实际表头填写（不要改列名）：

列名填法
主体形变(0容忍:无/有)无 = 未发现形变；有 = 发现形变，直接判 FAIL
Logo变字(无/有/不适用)无 / 有 / 不适用
提环杯盖结构(无/有/不适用)无 / 有 / 不适用
反光结构(无/有/不适用)无 / 有 / 不适用
结论(PASS/FAIL)PASS / FAIL
备注写明具体问题，例如「杯盖右侧卡扣缺一角」
这里的 无 / 有 指「无问题 / 有问题」，不是「有没有这个结构」；结构本身不存在时填 不适用。
建议两个人各看一遍（业务 + 美工），有分歧的 case 单独标出来复核。

08 门禁怎么判

通过 = (形变 = 0 容忍全部满足) 且 (PASS >= 7/10)
不过线 = 止损，不进入 M1 正式管线开发

只要出现 1 例确凿的主体形变，就按「0 容忍」处理，先定位是抠图、合成还是模型的问题，修完复跑，不要靠降低标准放行。
